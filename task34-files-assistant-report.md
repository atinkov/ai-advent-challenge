### Модуль 02. Первый сценарий на Gatling

**05. Session и EL-выражения.md**
- **Стр. 142** — теоретический разбор (раздел 3.2 «Обработка ошибок внутри функции»): объясняется, что исключение внутри `exec(session -> ...)` помечает сессию неуспешной, но не останавливает сценарий; чтобы пользователь остановился после такой ошибки, сразу за шагом ставят `exitHereIfFailed()`. Ссылка на урок 12.

**08. Авторизация и получение списка счетов.md**
- **Стр. 82** — код: `.exitHereIfFailed()` в конце `LoginScenario.run()` (после `buildLoginRequest() → login() → setAccessToken()`).
- **Стр. 110** — пояснение к этому коду: завершает виртуального пользователя, если логин не удался, чтобы без токена не уходить в каскад ошибок авторизации на всех следующих запросах.
- **Стр. 171** — раздел «Частые ошибки»: отсутствие `exitHereIfFailed()` после логина превращает одну ошибку авторизации в серию ошибок на всех следующих шагах.

**11. Сценарий — перевод между своими счетами.md**
- **Стр. 311** — код: `.exitHereIfFailed()` после `transferService.getAccountWithSufficientBalance(...)` — выбор счёта с достаточным балансом; если счёт не найден, перевод выполнять бессмысленно.
- **Стр. 315** — код: `.exitHereIfFailed()` после `transferService.getTargetAccount()` — выбор счёта-получателя; без него тело запроса перевода не может быть корректно собрано.

**12. Проверки и ассерты в Gatling.md**
- **Стр. 84** — теория (раздел 2.7 «Управление потоком после провала»): `exitHereIfFailed()` — инструмент для прерывания сценария сразу после неуспешного шага.
- **Стр. 93** — пример кода: `).exitHereIfFailed()` после запроса логина с проверками `status().is(200)` и `jsonPath("$.accessToken")`.
- **Стр. 96** — пояснение: не авторизовавшийся пользователь не перейдёт к переводу/пополнению, ошибка в отчёте видна как ошибка авторизации, а не как серия производных ошибок.
- **Стр. 215** — «Частые ошибки»: отсутствие `exitHereIfFailed()` после критичного шага (в первую очередь авторизации) маскирует первичный сбой множеством разных ошибок.
- **Стр. 221** — «Рекомендации по проектированию»: каждый запрос, результат которого используется на следующем шаге (авторизация, получение идентификатора), должен завершаться `exitHereIfFailed()`.

### Модуль 04. Моделирование нагрузки

**02. Закон Литтла на практике.md**
- **Стр. 353** — таблица «Как читать расхождение» (раздел 7): если `L` в отчёте меньше расчётного — одна из причин: сессии завершаются раньше из-за выхода после ошибки (`exitHereIfFailed`).

**04. randomSwitch и профиль нагрузки.md**
- **Стр. 83** — код: `.exitHereIfFailed()` после группы `LOGIN` в сценарии сессии (логин + получение счетов выполняются один раз, затем `repeat` с `randomSwitch` по операциям).
- **Стр. 105** — разбор решения: без токена все операции упадут с `403`, и отчёт заполнится ошибками, не связанными с тестируемыми операциями.
- **Стр. 226** — раздел 5.1: при провале проверки внутри ветки и `exitHereIfFailed` последние запросы ветки не выполняются — поэтому распределение по весам нельзя проверять по числу запросов внутри ветки.

**05. Pacing — фиксированная частота итераций.md**
- **Стр. 43** — минусы pacing: выбывшие пользователи не возвращаются — если пользователь завершился по `exitHereIfFailed()`, частота тихо падает; упоминается, что `LoginScenario` воркшопа вызывает `exitHereIfFailed()` после логина.
- **Стр. 343** — «Частые ошибки»: `exitHereIfFailed()` внутри `forever` выводит пользователя из теста насовсем при первой ошибке; для прерывания только текущей итерации нужен `exitBlockOnFail()`.

**06. Разные способы воспроизведения профиля нагрузки.md**
- **Стр. 107** — вариант A (сессия в `forever`): `exitHereIfFailed()` внутри `forever` завершает пользователя целиком, а не итерацию; `exitBlockOnFail()` это не отменяет, т.к. `LoginScenario` сам вызывает `exitHereIfFailed()` после логина.
- **Стр. 215** — вариант B (сценарий на операцию): `exitBlockOnFail()` прерывает только итерацию, но ошибка логина всё равно завершает пользователя, потому что `LoginScenario` вызывает `exitHereIfFailed()`.
- **Стр. 325** — раздел 5.1: выход фактического числа операций за диапазон ±2σ может означать, что часть сессий обрывается раньше времени (ошибки логина, `exitHereIfFailed` в операциях).
- **Стр. 420** — «Частые ошибки»: `exitHereIfFailed()` внутри `forever` в варианте B — единственный пользователь редкого сценария после первой ошибки выбывает, и операция пропадает из теста; использовать `exitBlockOnFail()`.
