# Ассистент поддержки пользователей (день 33)

Мини-сервис поддержки вымышленного продукта TaskFlow: отвечает на вопрос клиента с учётом его тикета.

| Часть | Где | Что делает |
|---|---|---|
| CRM через MCP | `week7/CrmMcpServer` + `support/crm.json` | stdio MCP-сервер над JSON с пользователями и тикетами: `get_ticket(ticket_id)` — тикет, события и карточка пользователя; `get_user(user_id \| email)`; `list_tickets(status)` |
| RAG | `week7/SupportKnowledge` + `support/kb/` | FAQ и документация продукта, нарезка по заголовкам (`## раздел › ### статья`), лексический поиск по основам слов с весом IDF |
| Ассистент | `week7/SupportAssistant` | вопрос + тикет → MCP `get_ticket` → поиск по вопросу и данным тикета → LLM через общий `LlmClient` → ответ «Причина / Что сделать» со ссылками [n] |
| Интерфейс | `week7/Task33` + `src/main/resources/task33/index.html` | веб-страница на `127.0.0.1:8033`, консольный режим, проверка задания |

## Запуск

```bash
mvn -q compile exec:java -Ptask33                                                    # веб-интерфейс http://localhost:8033
mvn -q exec:java -Ptask33 -Dexec.args="ask T-1002 Почему не работает авторизация?"  # ответ в консоли
mvn -q exec:java -Ptask33 -Dexec.args="check"                                       # 3 проверки → task33-support-report.md
```

Переменные: `TASK33_PORT` (8033), `TASK33_OPEN_BROWSER` (1); LLM — как у всех дней (`LLM_API_KEY`, `HINDSIGHT_API_LLM_*` в `.env`).

## Демо

Один вопрос «Почему не работает авторизация?» по трём тикетам даёт разные ответы:

| Тикет | Что в CRM | Ответ |
|---|---|---|
| T-1001 | 5 неудачных входов, аккаунт `locked` | блокировка на 30 минут → подождать или сбросить пароль |
| T-1002 | Enterprise, вход через SSO, истёк сертификат IdP | администратору обновить сертификат в настройках SSO |
| T-1003 | 2FA TOTP, часы телефона отстают на 3 минуты | включить автоматическое время на телефоне |

## Проверка задания (`check`)

1. **CRM через MCP** — сервер отдаёт `get_ticket`, `get_user`, `list_tickets`; `get_ticket(T-1001)` возвращает тикет и пользователя из `support/crm.json`.
2. **RAG** — в базе знаний есть разделы FAQ и документации; поиск по ошибке SSO находит статью про SSO.
3. **Контекст тикета** — один и тот же вопрос по T-1001 / T-1002 / T-1003: в каждом ответе причина из данных тикета, найдена нужная статья FAQ, есть ссылки [n], ответы различаются.
