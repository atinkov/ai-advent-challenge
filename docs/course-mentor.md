# AI-наставник курса НТ (день 35, «реальная задача»)

## Какую задачу решаем

Курс `lmru--qacc--performance-qa-course` — ~60 уроков и заданий по нагрузочному тестированию, практика — код Gatling (Java)
поверх банковского стенда. Узкое место курса — преподаватель:

1. **Проверка домашних заданий.** У задания 02/12.1 девять требований; проверить каждое по коду студента, найти, где именно
   ошибка, и объяснить — 15–30 минут на одно решение.
2. **«Я застрял».** Нужна подсказка, которая продвигает, но не выдаёт готовое решение.
3. **Ещё практики.** Ученик ошибся в `exitHereIfFailed` и ожидаемых отказах — ему нужна новая задача именно на это,
   а в курсе по уроку одно задание (или ни одного).

Наставник берёт эти три работы на себя и работает на реальном курсе (файлы уроков и заданий) и реальной LLM из `.env`.

## Как участвует AI и где его страхует код

| Шаг | Код (детерминированно) | LLM |
|---|---|---|
| Разбор задания | из файла задания курса: требования R1…Rn (нумерованные пункты, пункты списков и абзацы «нужно / обосновать» раздела «Требования»), критерии, урок по ссылке «К уроку» | — |
| **Проверка ДЗ** | нумерует строки кода студента; у каждого «выполнено» проверяет цитату-доказательство в файлах студента (без неё → «частично»); отбрасывает замечания к несуществующим файлам; **вердикт «зачтено» считает сам** — только если выполнены все требования; пишет историю | оценивает каждое требование по коду (met / partial / missing + цитата + комментарий), находит ошибки с файлом и строкой, предлагает следующий шаг |
| **Подсказка** 1–3 | проверяет: код ≤ 3 строк, вызовы в коде есть в DSL курса или в коде студента (ловит выдуманное `if("#{flag}")` вместо `doIfOrElse`), «Где посмотреть» — настоящий раздел урока; иначе — одна переделка, длинный код скрывается | наводящий вопрос → конструкция и раздел урока → план решения, с привязкой к строкам кода студента |
| **Новая задача** | собирает урок, пример оформления задания курса, эндпоинты стенда (все `/api/v1/…` из курса), список заданий курса, **слабые места ученика** из прошлых проверок; проверяет разделы, число пунктов, что эндпоинты есть на стенде, что нет готового кода, что не дубль (сходство слов < 0,5) | пишет задание в формате курса |

История — `mentor-output/progress.json` (проверки с невыполненными требованиями, подсказки, задачи); отчёты проверок —
`mentor-output/reviews/`, задачи — `mentor-output/tasks/`.

## Запуск

```bash
mvn -q compile exec:java -Ptask35                                              # веб: http://localhost:8035
mvn -q exec:java -Ptask35 -Dexec.args="assignments"                          # задания курса и их требования (без LLM)
mvn -q exec:java -Ptask35 -Dexec.args="review 12.1 ../my-gatling/src/test/java"
mvn -q exec:java -Ptask35 -Dexec.args="hint 12.1 --level 2 --code ../my-gatling/src Почему снятие падает в KO?"
mvn -q exec:java -Ptask35 -Dexec.args="task 02/13 --level сложный"          # без --focus — по слабым местам
mvn -q exec:java -Ptask35 -Dexec.args="progress"
mvn -q exec:java -Ptask35 -Dexec.args="check"                                # проверка задания дня → task35-mentor-report.md
```

Задание можно указать номером (`12.1`, `02/12.1`), частью названия или путём. Веб-страница: выбор задания, код решения
(несколько файлов — через строку `// FILE: Имя.java`), подсказка, новая задача по уроку, прогресс.
Env: `TASK35_COURSE_DIR`, `TASK35_STUDENT`, `TASK35_PORT` (8035), `TASK35_OPEN_BROWSER`; LLM — `.env` как у всех дней.

### В репозитории студента (CI)

`review --out review.md --strict` завершается с кодом 1, если задание не зачтено, — тот же приём, что в дне 32:

```yaml
- run: mvn -q -B compile exec:java -Ptask35 -Dexec.args="review 12.1 $GITHUB_WORKSPACE/student/src --out $GITHUB_WORKSPACE/review.md --strict"
  working-directory: AIAdventChallenge
  env: { LLM_API_KEY: ${{ secrets.LLM_API_KEY }}, TASK35_COURSE_DIR: ${{ github.workspace }}/course }
- uses: marocchino/sticky-pull-request-comment@v2
  with: { path: review.md }
```

Для этого нужен доступ CI к репозиторию курса и ключ LLM — в этом проекте workflow не заводится.

## Проверка (`check`)

На двух решениях задания 02/12.1 из `mentor/samples/` (см. [README](../mentor/samples/README.md)):
верное должно быть зачтено 9/9 с подтверждёнными цитатами; в решении с ошибками должны быть найдены все 5 заложенных
ошибок (R1, R3, R4, R8, R9) с привязкой к строкам; подсказка уровня 2 — без готового решения и выдуманного API, со ссылкой
на настоящий раздел урока; новая задача к уроку 02/13 — валидна и сфокусирована на слабых местах из проверки.

## Ограничения

- Наставник не запускает код студента: нет стенда и Gatling в окружении наставника. Требования «по отчёту» оцениваются
  по тому, обеспечивает ли их код. Следующий шаг — компиляция и короткий прогон на стенде в CI.
- Разбор требований рассчитан на практические задания с разделом «Требования»; у теоретических заданий (01.1, 03.1, 04.01.1)
  требований не находится — для них работают подсказки, а проверка ответов — нет.
- Цитата подтверждает, что строка есть в коде, но не что она верна по смыслу — смысл остаётся за LLM.
