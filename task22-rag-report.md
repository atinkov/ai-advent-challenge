> 
> - **Избежать конфликтов** с другими зависимостями, которые тянут свою (возможно, несовместимую) версию Jackson.

### Q4. По какому правилу McpRegistry формирует имена инструментов в общем каталоге и почему выбран именно такой разделитель?

- **Ожидание:** Имя = <сервер>__<инструмент> (двойное подчёркивание), потому что имена функций OpenAI допускают только [a-zA-Z0-9_-].
- **Источники, где есть ответ:** `AGENTS.md`, `McpRegistry.java`, `task20-orchestration-report.md`

**Без RAG** — фактов 1/2; не найдено: `__`

> В `McpRegistry` имена инструментов в общем каталоге формируются по шаблону:
> 
> ```
> {serverName}:{toolName}
> ```
> 
> Разделитель — двоеточие `:`.
> 
> **Почему именно двоеточие:**
> 
> 1. **Не входит в допустимый набор символов** для `toolName` по спецификации MCP (там разрешены `[a-zA-Z0-9_-]`), поэтому коллизия с «внутренним» именем инструмента невозможна.
> 2. **Визуально чёткое разделение** — при логировании и в UI сразу видно, какой сервер и какой инструмент.
> 3. **Не конфликтует с другими разделителями**, которые могут встречаться в именах: точка (пакеты/классы), слэш (пути), подчёркивание (часть имени).
> 4. **Совпадает с URI-подобной конвенцией** (`scheme:rest`), привычной для Java-разработчиков.
> 
> При разборе обратно (`parse`) `McpRegistry` ищет **первое** вхождение `:` — всё до него → `serverName`, всё после → `toolName`. Это гарантирует однозначность, даже если `toolName` сам содержит `:` (что по спеке не должно, но защита от мусора).
