## Замечания к коду

- `AuthEndpoint.java:16` — jmesPath("accessToken").saveAs("accessToken") не содержит матчера валидации: если поле отсутствует или равно пустой строке, check не провалится, и последующие запросы уйдут с пустым токеном. *Подсказка:* В уроке, раздел 2.4, показано, что перед saveAs можно поставить notNull() или exists(), а для проверки непустоты — not(""). Добавь матчер до saveAs, чтобы провалить check при пустом токене.
- `OperationsSimulation.java:23` — После .exec(auth.login()) нет exitHereIfFailed(). При сбое логина виртуальный пользователь продолжит сценарий и сгенерирует каскад ошибок на dashboard, deposit, transfer, withdraw. *Подсказка:* Раздел 2.7 урока: чтобы прервать сценарий после неуспешного шага, добавь exitHereIfFailed() к exec, содержащему login. Пример приведён прямо в уроке.
- `AccountEndpoint.java:26` — Метод transfer() содержит только проверку статуса 200, без проверки содержимого тела ответа. Не подтверждено, что перевод действительно выполнен. *Подсказка:* Раздел 2.5 урока: к одному запросу можно присоединить несколько check(). Добавь проверку конкретного поля из ответа (например, id операции или статус перевода), как это сделано для deposit на строке 18.
- `AccountEndpoint.java:34` — withdraw() проверяет только status().is(200). Ожидаемый ответ 400 при превышении баланса будет засчитан как KO и исказит метрику успешности прогона. *Подсказка:* Раздел 2.3 и 5 урока: если среди ожидаемых кодов есть значение вне диапазона 200–209, явная проверка обязательна. Используй status().in(200, 400) или разбей на ветки с собственными check, чтобы 400 не считался технической ошибкой.
- `OperationsSimulation.java:30` — В assertions отсутствует отдельное условие на нулевое количество неуспешных запросов авторизации (details("Login").failedRequests().count().is(0L)). *Подсказка:* Раздел 3.2 урока: селектор details("Login") применяет условие только к запросам с именем "Login". Добавь третье условие в assertions, чтобы сбой авторизации всегда падал прогон независимо от общей доли успешных.
- `OperationsSimulation.java:31` — Нет комментария, обосновывающего выбор порогов 99.0 % и 1500 мс. *Подсказка:* Требование R9: рядом с assertions(...) добавь короткий комментарий (// или /* */), объясняющий, почему выбраны именно эти значения (например, SLA сервиса, результаты пилотного прогона и т. п.).
